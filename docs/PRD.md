## 1. 产品目标和使用场景

### 1.1 背景
此前欠料跟踪依赖企业微信里的「机器人」通过聊天方式查询欠料表，缺少标准流程、缺测试、缺存档，且数据未做本地持久化。本次将其**重做成一个本地运行的浏览器 APP**，沿用已验证的业务逻辑（数据来源、解析规则、汇总口径、交期对比、状态过滤），但采用标准开发流程、独立文件夹、本地数据库、可测试。

### 1.2 产品目标
- 提供一个**本地、可离线查询**的欠料看板，不再依赖聊天机器人。
- 数据从企业微信欠料在线表**同步**到**本地数据库**，重启电脑不丢失。
- 覆盖核心查询场景：总览、明细搜索、项目汇总、物料汇总、品牌汇总、交期对比、状态过滤。
- 同步过程对用户可见（进度、上次成功时间、失败提示）。

### 1.3 使用场景
- 采购/跟单人员每日打开 APP，点「同步」拉取最新欠料，查看哪个项目、哪种物料缺多少。
- 按品牌（如富士金、Siemens）汇总，快速判断某品牌的欠料总量与分布。
- 问「某物料交期来不来得及」：用供方「预计交期」对比需求方「期望交期」，给出风险提示。
- 已解决/归档的条目（含隐藏行/分表）自动排除，避免干扰。

## 3. 各模块的功能和用途

### 3.1 总览（Dashboard）
- **用途**：一眼掌握全局欠料态势。
- **功能**：
  - 4 张指标卡：总欠料条数、合计欠料数量、紧急条目数（空白/无交期/付款瓶颈）、已同步分表数。
  - 紧急度分布图（空白 / 无交期 / 付款瓶颈 / 有交期 / 其他）。
  - 项目欠料 TOP10 条形图。
  - 点击项目条 → 跳「项目汇总」带入该项目。

### 3.2 查询（Search）
- **用途**：按关键词检索欠料明细。
- **功能**：
  - 输入框 + 类型下拉（自动 / 项目 / 物料编码 / 物料名称 / 品牌）+ 搜索按钮。
  - 结果表格字段：项目、物料编码、物料名称、品牌、规格、欠料数量、紧急度、预计到货、状态。
  - 支持口语：自动剥离「XX项目」「XX品牌」「XX材料」等尾缀（如「富士金品牌」「巨茂项目」）。
  - 表头排序、点击行展开详情。

### 3.3 项目汇总（Project Summary）
- **用途**：查看某项目整体欠料与按物料的明细；未输入时默认展示全部项目汇总。
- **功能**：
  - 项目名/编码输入；**留空则展示全部项目列表**（项目、合计数量、紧急度、来源表），按欠料量排序。
  - 输入后输出：总条数、合计欠料量、紧急度分布、**以物料编码为单位**的缺料明细（编码、名称、品牌、合计数量、紧急度）。
  - 点击左侧「项目汇总」导航即自动加载默认全部项目；搜索后切换为该项目明细。

### 3.4 物料汇总（Material Summary）
- **用途**：跨项目看某物料的欠料总量；未输入时默认展示全部物料汇总。
- **功能**：
  - 物料编码/名称输入（如 `B07-05-00-03-10`、`减压阀`、`Siemens`）；**留空则展示全部物料列表**（编码、名称、合计数量、涉及项目数、紧急度）。
  - 输入后额外展示：按项目分布、明细 Top20。
  - 点击左侧「物料汇总」导航即自动加载默认全部物料；搜索后切换为过滤结果。

### 3.5 品牌汇总（Brand Summary）★ 新增
- **用途**：按品牌维度汇总欠料；未输入时默认展示全部品牌汇总。
- **功能**：
  - 品牌输入或下拉（如 富士金 / Siemens）；**留空则展示全部品牌列表**（品牌、合计数量、涉及物料数、紧急度）。
  - 输入后输出：该品牌总条数、合计欠料量、按物料编码分布、按项目分布、明细表。
  - 点击左侧「品牌汇总」导航即自动加载默认全部品牌；搜索后切换为该品牌明细。

### 3.6 交期对比（ETA Check）
- **用途**：判断某条目/项目交期是否赶得上需求；未输入时默认展示全部欠料的交期对比。
- **功能**：
  - 项目/物料输入；**留空则展示全部欠料**的交期对比卡片。
  - **按物料编码聚合**：同一物料编码跨项目/多行合并为一张卡片，顶部显示编码、名称、涉及项目。
  - 每张卡片内按项目列出「需求交期（期望交期） vs 实际预计到货（预计到货时间）」的时间轴对比：
    - 灰色竖线 = 今天；橙色标记 = 需求交期；蓝色标记 = 实际预计到货；
    - 两标记之间红色段 = 逾期缺口，绿色段 = 提前余量；
    - 文字标注剩余/逾期天数、相差天数、判定结果（逾期 / 提前 / 刚好 / 缺交期信息）。
  - 顶部指标卡：匹配条数、逾期风险、来得及、缺交期信息。
  - ⚠️ 注意：`预计到货时间` 只读供方承诺列（预计到货时间 / 材料预计到货时间），**不读**需求方写的「期望到货时间」；期望交期仅用于对比。

### 3.7 数据同步（Sync）
- **用途**：从企微欠料表拉取最新数据入库。
- **功能**：
  - 「立即同步」按钮 + 进度条 + 日志区（成功/失败条数、耗时）。
  - 显示上次成功时间、各分表条数、失败提示与重试。
  - 失败时保留上次成功数据，不覆盖。

### 3.8 设置（Settings）
- **用途**：配置与查看。
- **功能**：
  - 数据源标识（企微表，只读展示，复制自原项目）。
  - 本地数据库路径。
  - 状态过滤关键词管理（已解决/归档/已完成/关闭/已到货/取消/作废 可勾选）。

### 3.9 钣金欠料（SheetMetal）★ 新增（v1.5）

## 4. 模块之间的关系

```
数据同步 ──写入──> 本地数据库 <──读取── 所有查询/汇总模块
                                      │
总览 = 数据库全量聚合（指标卡 + 紧急度 + 项目TOP）
查询 = 数据库模糊检索（项目/编码/名称/品牌）
项目汇总 = 查询(项目) + 按物料编码聚合
物料汇总 = 查询(物料) + 按物料编码跨项目聚合
品牌汇总 = 查询(品牌) + 按物料编码/项目聚合
交期对比 = 查询 + 预计 vs 期望 日期对比
所有模块 ──统一经过──> 状态过滤（排除已解决/归档）
```

- 数据同步是**唯一写入**入口；其余模块均为**只读**查询。
- 状态过滤是所有查询的统一前置（在查询入口排除已解决/归档条目）。

## 5. 本地数据保存和备份要求

- **存储**：本地 SQLite 数据库文件（位于 APP 文件夹内，如 `data/shortage.db`）。
- **持久化**：所有同步结果入库；APP 关闭、电脑重启后从库读取，**无需重新同步即可查询**。
- **同步原子性**：同步成功才提交；失败保留上次成功数据。
- **备份**：
  - 数据库文件随项目文件夹，纳入 Git 版本管理（见 Step 6）。
  - 建议定期复制 `data/shortage.db` 作离线备份（第一版可手动，后续可加自动备份）。
- **隔离**：新项目位于独立文件夹 `D:\InvoiceTool\shortage_app\`，**不修改、不移动、不删除**原 `shortage_tool` 任何文件。

## 8. 关键业务规则（从原项目继承，须严格遵守）

- **交期语义**：`预计到货时间` 仅取供方承诺列；`期望到货时间` 是需求方写的，单独存为「期望交期」，仅用于交期对比。
- **列名别名**（不同子表表头不一致，解析时需自适应）：
  - 项目：项目 / 项目名称 / 申请部门 / 领用车间（新增「项目名称」以适配规范后的在线表表头）
  - 欠料数量：欠料数量 / 待领数量
  - 预计交期：预计到货时间 / 材料预计到货时间
  - 期望交期：期望到货时间 / 期望交期
  - 状态：状态 / 处理状态 / 进度 / 是否解决 / 备注
- **状态过滤关键词**：已解决/归档/已完成/完成/已关闭/关闭/已领/已到货/已到/解决/取消/作废（命中即排除）。
- **口语尾缀剥离**：查询关键词提取后须剥离「品牌/材料/物料/型号/系列/规格/配件/零件/项目/公司/厂家」等尾缀。
- **隐藏行/分表**：markdown 导出不含隐藏标记，无法自动识别；可靠机制是状态列过滤。用户后续会在表里加状态列；加列前隐藏行仍计入（已知限制）。
- **纵向合并单元格**：wecom-cli 导出 markdown 时合并单元格只在首行保留值。解析时对 项目编码/项目/单据编号/申请部门/单据日期/期望交期/预计到货时间 做前向填充；其中日期类字段（期望交期/预计到货时间）限制在同一单据编号内填充，避免跨单据污染。
- **人工到货/解决覆盖**：用户在项目汇总界面点击「确认到货」或输入快速登记文本后，系统把（项目 + 物料编码）写入 `manual_overrides` 表，并在同步后自动将该组合标记为 `manual_status = 已到货（人工）`，从而在看板中剔除；该记录随 `seed.sql` 同步到云端。
- **写回到货（方案 B，v1.3 新增）**：确认到货时，除本地覆盖外，还会**回写企业微信在线表对应单元格的状态列**（默认写「已到货」）。写前经用户预览确认（展示将改哪个子表、第几行、旧值→新值），并带多重安全闸（子表单表连续、唯一命中、坐标在界内、状态列存在）。**前提**：连接的智能机器人需对该在线表拥有【编辑】权限，否则写回会返回 `851003 no authority`（本地看板仍正常更新）。详见第 10 节。

## 9. 部署与运行架构（v1.1 新增，v1.2 补充人工覆盖）

### 9.1 两种运行形态
- **本地 APP**：Windows 上 `pythonw` 后台常驻（注册表 `HKCU\Run\ShortageApp` 登录自启，无窗、不弹黑窗），访问 `http://localhost:8765`。
- **云端部署**：Render Web Service（`https://shortage-app.onrender.com/`），Auto-Deploy 开启；代码 push 或数据 `seed.sql` push 均触发重部署。

### 9.2 数据同步与一致性
- 本地为**唯一写入源**：`app.py` 后台定时从企微同步 → 写入 SQLite → 导出 `seed.sql` 快照 → 推送 GitHub。
- 云端无 wecom-cli / 企微登录态，启动时从 `seed.sql` 初始化（含 `meta.last_sync` / `last_count`，故云端能显示「上次同步时间」）。
- 单实例保护：Windows 命名互斥体 `Global\ShortageAppSingleton`，防重复实例互相干扰。
- 可插拔数据源：配置 `WECOM_API_CORP_ID/SECRET/TABLE_DOCID` 时云端可直连企微 API；未配置则回退 wecom-cli（本地）。

### 9.3 已知限制
- 云端数据实时性依赖本地进程常开 + 自动推送；本地关机期间云端数据为最近一次快照。
- 在线表表头需保持约定列名（含「项目」或「项目名称」），否则物料会 fallback 到申请部门/领用车间；已对双「项目编码」异常表头做兜底（详见 CHANGELOG `33ae048` / `983ed8a`）。

## 10. 人工到货/解决覆盖与在线表写回 —— 已删除（v1.4）

### 10.1 原功能
- **本地人工覆盖**：项目汇总每行提供「确认到货」按钮，顶部提供「快速到货登记」文本框；命中行写入 `manual_overrides` 表，并在同步后通过 `manual_status` 列在看板中隐藏。
- **在线表写回（方案 B）**：本地标记时同步把企业微信在线表对应行的状态列改写为「已到货」，使源头数据一致。

### 10.2 删除原因（2026-08-13）
- 企业微信 **10 人以上企业模式**下，API 模式机器人仅可编辑**自己创建**的文档/表格，不会继承授权用户对成员手工创建文档的编辑权（官方帮助文档明文限制）。
- 欠料在线表由成员手工创建，机器人调 `sheet_update_range_data` 始终返回 **`851003 no authority`**，即便已在后台授权「新建和编辑文档」仍无效——这是平台对象级权限限制，非代码缺陷、非文档分享权限问题。
- 在无法写回原始表的情况下，单独的「本地标记/隐藏」功能对用户无意义；经用户确认，**彻底删除**「确认到货」「快速到货登记」、`manual_overrides` 表及 `manual_status` 列。

### 10.3 当前行为
- 项目汇总仅保留只读欠料明细，无操作列、无到货登记入口。
- 所有欠料/到货状态以企业微信在线表的「状态」列为准；若需隐藏某行，请直接修改原始在线表的状态列（如改为「已到货」「已归档」「已解决」），下次同步后看板自动过滤。
- `writeback.py` 已从仓库移除；`sync.py` 的 `sheet_get_info` / `sheet_update_range_data` 等写接口封装亦被移除。如未来需要写回能力，须改用企业微信「自建应用」官方 API 重新实现。
